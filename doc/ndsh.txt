*ndsh.txt*  Neovim chat UI for DeepSeek Harness

==============================================================================
INTRODUCTION                                                          *ndsh*

ndsh renders a chat panel for a dsh runtime (`dsh --profile sdk`) in native
Neovim windows. The panel has two panes: the message pane (transcript) on
top and the chat (input) pane below.

==============================================================================
PANEL KEYS                                                      *ndsh-keys*

These keys are buffer-local to the panel and stable. Leader-prefixed
mappings are NOT documented here: they are user configuration (see
|ndsh-config-keys|) and may be changed freely.

Message pane (readonly transcript):
  q              Close the panel (detaches the session)
  i              Jump to the input pane, insert mode
  s              Scan messages (telescope or vim.ui picker), jump to one
  J / K          Jump to next / previous message block (tool outputs open)
  <Tab>          Toggle the fold under cursor (same as |za|)
  za             Toggle fold: tool results and reasoning blocks
  zR / zM        Open / close all folds (native)
  /              Search the transcript (native)
  All other normal-mode motions, yank, and marks work natively.

Input pane:
  <C-s>          Send message (insert and normal mode)
  <CR>           Insert mode: plain newline. Normal mode: send.
  <C-x><C-u>     Complete slash command after a leading "/"
  <Esc>          Normal editing as usual; the buffer is a normal buffer.

Window management:
  <C-w>h/j/k/l   Native window navigation works everywhere
  <C-w>> etc.    Native resizing works on the panel windows

==============================================================================
SLASH COMMANDS                                                *ndsh-slash*

Slash input is highlighted live while typing and completes with <C-x><C-u>.

Local commands — handled by the plugin, never sent to the wire:

  /new [name]        Create a session and swap the panel to it
  /rename {name}     Rename the current session (shown on its winbar)

Runtime commands — routed natively by the dsh SDK profile (verified
against a live runtime; unknown slash text is sent to the wire unchanged):

  /compact           Compact the conversation context
  /goal {objective}  Set a session goal
  /plan              Toggle plan mode

Not routed in the sdk profile (they fall through to the model as plain
prompts; they are Host/Web-side commands): /export, /feedback,
/permission. The runtime also accepts the Chinese spellings 压缩 目标
计划 for the routed commands. This list mirrors the verified set until
the SDK exposes a catalog query.

==============================================================================
COMMANDS                                                     *ndsh-commands*

  :NDSHToggle        Toggle the panel
  :NDSHOpen          Open the panel
  :NDSHClose         Close the panel
  :NDSHNew [name]    Create a session and swap the panel to it
  :NDSHResume        Resume the most recently active session
  :NDSHSessions      Session navigator (telescope or vim.ui picker;
                     <C-d> in the telescope picker deletes an entry)
  :NDSHMessages      Scan transcript messages and jump to one
  :NDSHRename [name] Rename the current session
  :NDSHDelete        Delete the current session (asks for confirmation)
  :NDSHConnect       Connect a provider (stores credentials)
  :NDSHModel         Select the active model (restarts the runtime)
  :NDSHStop          Stop the runtime
  :NDSHRestart       Restart the runtime
  :NDSHInstallRuntime  Install the managed runtime: a pinned Node.js +
                     @deepseek-ai/dsh under stdpath("data")/ndsh/bootstrap
  :NDSHLog           Show the captured runtime stderr log
  :NDSHDemo          Play a scripted demo session

==============================================================================
CONFIGURATION                                                  *ndsh-config*

setup({}) accepts, among others:
  layout            "right" | "bottom" | "float"
  input_height      input pane rows
  restore           "quit" | "dashboard" | "scratch" | fun(win)
  store_path        credentials/session store location
  dsh.version       pinned @deepseek-ai/dsh version for the managed runtime
  dsh.node_version  pinned Node.js release for the managed runtime

                                                          *ndsh-runtime*
Runtime argv resolution order: dsh.cmd, `dsh` on $PATH, the managed
bootstrap runtime, then a ~/workspace/deepseek-harness source checkout.
With nothing resolvable, first use offers to bootstrap the managed runtime
(needs curl, tar, sha256sum); :NDSHInstallRuntime repeats or repairs it.

                                                          *ndsh-config-keys*
Key mappings are fields under keys = {} and are intentionally user-owned.
ALL of them default to nil: ndsh defines no global mappings on its own.
  keys.toggle       panel toggle
  keys.sessions     session navigator
  keys.messages     transcript message scanner
  keys.resume       resume the most recently active session
  keys.model        model selector
  keys.new_session  new session
  keys.send         list of send keys in the input pane (default <C-s>)
  keys.tabnext      tabpage navigation inside panel windows
  keys.tabprev      tabpage navigation inside panel windows

Example:
>
  require("ndsh").setup({
    keys = {
      toggle = "<leader>ant",
      sessions = "<leader>ans",
      messages = "<leader>anm",
      resume = "<leader>anr",
      model = "<leader>anM",
      new_session = "<leader>ann",
    },
  })
<

==============================================================================
CHROME                                                          *ndsh-chrome*

The message pane winbar shows the session name (● marks unread activity).
The input pane winbar shows agent status (an ASCII spinner while running),
the active model on the left, and on the right the plan/build mode
(colored; follows /plan toggles via plan/mode events), the working
directory, and context usage (used/window · %).

Sessions persist across nvim restarts (sessions.json beside the store), and
each session's transcript is saved beside it (transcripts/<id>.md) and
reloaded on activation; activating a stored session resumes its wire
session. Wire sessions are stored per working directory by dsh: a session
restored under a different cwd starts fresh, transcript kept.
